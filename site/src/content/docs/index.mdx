## Why

The stock firmware runs ByteDance's DataFinder telemetry SDK. It reports more
than 35 kinds of event, from every boot to every mute, keyed to the Wave's
serial number, with no visible opt-out. It uploads meeting audio, transcripts
and voiceprints to Insta360's cloud, to a data centre picked by region, and
releases up to 1.0.13.6 ran a root shell over telnet with the password
`123456`. The evidence is in the
[Security Q&A](/insta360-custom-firmware/research/security/). It also signs
its updates with a 512-bit RSA key, a size that can be factored on ordinary
hardware: see the
[reverse-engineering report](/insta360-custom-firmware/research/report/#soc-firmware-update-flow).

## What you get

<CardGrid>
  <Card title="No telemetry" icon="padlock">
    The installer stubs out the stock app and empties its telemetry library, so
    neither runs. By default waved's only outside contact is the clock: it asks
    `pool.ntp.org` and `time.google.com` for the time, and you can change both.
    The webhook and update servers stay empty until you set them.
  </Card>
  <Card title="Your recordings" icon="document">
    Recordings are made on the Wave and kept there until you send them. With a
    webhook set, each one is sent to your server as one HTTP `POST`, queued on
    the Wave so it survives a restart, and retried when a send fails. When the
    Wave runs low on space, it removes only recordings your server has already
    received, oldest first. The full failure test on a Wave is still to do.
  </Card>
  <Card title="A real speakerphone" icon="laptop">
    Plug it into a computer and it works as a USB speakerphone (USB Audio Class
    2) with echo cancellation and beamforming. Verified on the Wave with a Mac.
  </Card>
  <Card title="Bluetooth audio and calls" icon="phone">
    Pair a phone for music and calls, and answer or decline on the Wave. Tested
    on the host so far.
  </Card>
  <Card title="Signed updates you host" icon="server">
    Update packages are signed with your own key and served from your own
    server. A new version runs on trial, and the Wave goes back to the old one
    if it fails. Tested on the host so far.
  </Card>
  <Card title="One script back to stock" icon="left-arrow">
    The installer never writes the Wave's system partition. `revert.sh` removes
    waved's files from `/data`, and the stock app starts again after a reboot.
  </Card>
</CardGrid>

## How it works

waved is a single Rust program. Each piece of hardware (the microphones and
speaker, the screen, the Bluetooth module, the battery and lift controller,
USB and Wi-Fi) has its own service, and the services share state through one
in-process bus. The start-up script runs it at boot and restarts it about 3
seconds after any exit.

## Status

Unofficial, not affiliated with Insta360, and reversible with one script. Use
it at your own risk. The core works on a real Wave: the
screens, USB audio with echo cancellation, recording, uploads, Wi-Fi setup and
the power key. Other parts, such as Bluetooth, signed updates, the PIN lock and
the Wave Controller app, are host-tested or not yet tried on a Wave. The
overview says which is which.
