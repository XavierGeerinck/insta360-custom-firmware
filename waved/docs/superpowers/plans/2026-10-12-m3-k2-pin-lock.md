# Milestone 3, K2: PIN lock — plan

**Goal:** enforce `security.device_password` as a 4–6 digit PIN (D10). Files, Wi-Fi,
Bluetooth, Uploads and System ask for it; mute, volume, Record, audio mode and noise
reduction never do. Unlocked until the screen rests. Five wrong tries mean a one-minute
wait. No PIN set means no prompt. The setup page accepts 4–6 digits only.

**Spec:** `../TODO.md` K2 and D10; `../docs/mockups/png/pin.png`; the PIN section of
`../docs/mockups/index.html`; `../docs/mockups/README.md` ("PIN keypad": title at top 6,
dots at top 36, 3 × 4 keys of 64 × 48 at x 96/168/240, y 56/110/164/218, no status).

Already in place from milestone 1/2: `Route::Pin(Box<Route>)`, `Route::guarded_by`,
`UiEvent::PinAccepted`, the router's unlock/relock logic and its tests,
`SettingsState::pin_enabled`, and Menu's lock icon. The runtime masks `pin_enabled`
until the PIN screen exists (R13); K2 removes the mask.

## Decisions

1. **The check lives in `waved-config`**, so the Wave Controller (J3,
   `verify_dev_passwd`) uses the same code:
   `pub fn verify_device_pin(security: &SecurityConfig, candidate: &str) -> bool`.
   The rate limit is a plain state machine next to it, `waved_config::PinAttempts`
   (`check(&mut self, security, candidate, now_ms) -> PinCheck`).
2. **Hash the PIN at rest.** config.toml keeps `pin1$<digits>$<iterations>$<salt>$<hash>`
   (PBKDF2-HMAC-SHA256, 16-byte random salt, 10 000 iterations), never the digits. The
   setup field is already write-only, so nothing needs the plaintext back, and the
   Wi-Fi PSK is already hashed the same way (`docs/WIFI.md`). Honest limit: 4–6 digits
   are at most 10⁶ guesses, so the hash only keeps the PIN out of config.toml, its
   `.bak` / `.unloadable` copies and anything copied off the device. The protection
   against someone who can read the file is its 0600 mode and K1.
3. **Migration on load, no `config_version` bump.** `WavedConfig::parse` hashes a plain
   4–6 digit `device_password` at once (hand edits keep working), and drops anything
   else with a warning: it was never enforced before K2 and the keypad can't type it.
   The next save (settings service or setup page) writes the hash.
   `validate_config` accepts only "" or a well-formed record.
4. **The runtime owns the attempts.** The screen sends `UiEvent::PinEntered(PinCode)`;
   `runtime::pin::PinGate` checks it against `ctx.config.security` and only then routes
   `PinAccepted`. One counter serves every PIN screen, so Cancel and reopen does not reset
   it; a `PinAccepted` from a screen is ignored. `UiSnapshot::pin` (`PinStatus`) tells the
   screen about wrong tries and the lockout. `PinCode`'s Debug never prints the digits.
5. **The PIN screen is never parked** under the resting screen: it is rebuilt on waking,
   so half-typed digits never survive a rest.
6. The PIN screen reads the PIN length from `ctx.config.security` (boot copy). Like
   `api.endpoint`, only the setup page changes it, and saving there restarts waved.
7. The wrong-try counter is in memory; a restart clears it.

## Tasks (TDD: failing test first)

1. **waved-config `pin.rs`.** Tests: RFC-style PBKDF2-HMAC-SHA256 vectors; 4–6 digit
   validity; a hash verifies its PIN only; two hashes of one PIN differ (salt); malformed
   records never verify; `pin_digits`; five wrong tries lock for 60 s, a locked check
   does not verify, the lock ends and resets; accept resets the count.
2. **Load, validate, form.** Tests: a plain PIN in a file loads hashed and verifies; a
   non-PIN value is dropped; a record survives a save/load round trip unchanged;
   validation rejects plaintext; the form rejects "123", "1234567", "12a4" with
   "Enter 4 to 6 digits", hashes "4821", blank keeps, clear removes.
3. **Setup page.** Test: the PIN field renders numeric with `pattern="[0-9]{4,6}"` and
   never the saved value.
4. **Keypad component.** Tests: key rects match the mockup and pass the tap limit; taps
   report `Key::Digit(n)` / `Cancel` / `Backspace`; disabled digits ignore taps.
5. **PIN screen.** Goldens: empty, two digits (pin.png), wrong, locked. Tests: typing the
   last digit sends `PinEntered` once; backspace; Cancel goes back; a new wrong try
   clears the dots; locked ignores digits; the lockout ends; a 6-digit PIN shows 6 dots.
6. **Runtime.** Tests: a set PIN shows the PIN screen in front of Files; the right PIN
   opens Files; five wrong tries keep the keypad locked for a minute; a screen's own
   `PinAccepted` unlocks nothing; resting relocks and a half-typed PIN is gone on waking;
   no PIN, no prompt.

## Device checks (integration pass)

- Set a PIN on the setup page; Files, Wi-Fi, Uploads and System ask for it; Volume,
  Audio mode, Noise reduction and Record do not.
- Five wrong tries: "Wrong PIN. Try again in 1 min."; the keypad works again after a minute.
- Let the screen rest or press the power key: the next locked row asks again.
- Time one PIN check on the device (expected well under 50 ms).
- A config.toml with `device_password = "4821"` loads; after the next save the file
  holds a `pin1$…` record.
