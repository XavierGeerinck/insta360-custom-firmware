# Display Redesign — Milestone 3, Workstream H: Updates (self-hosted, signed) — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** waved updates itself from a server its owner runs: a signed package format (H1), a
service that polls, downloads, verifies, installs and reboots (H2), the firmware update screen
(H3), and a written way back to stock (H4, research only). Design and decisions go into
`docs/UPDATES.md`.

**Architecture:**
- **One new crate, `crates/waved-update`.** It depends on `waved-state` only (plus crypto and
  HTTP crates). It holds the package format, the server index, version ordering, the install
  gate, the trial-boot bookkeeping, the `Installer` trait with its file-system implementation
  and a host fake, the `Fetcher` trait with its HTTP implementation, and `UpdateService`.
- **The signing tool is a binary of the same crate**, `waved-pack`, run on the host. The private
  key lives outside the repo; the public key is compiled into waved from `WAVED_UPDATE_PUBKEY`.
- **Fall-back is file-level, inside `/data`.** The stock A/B slots and the bootloader are never
  touched. `S60waved` counts starts of a new binary and swaps `waved.prev` back after three
  starts without a health report.
- **State out, commands in.** `OtaState` on a new watch channel; `Command::CheckForUpdate` and
  `Command::InstallUpdate`. The UI reads `snap.ota`.

**Tech stack:** Rust 2021 (stable 1.94), `ed25519-dalek` 2 (pure Rust), `sha2` 0.10 and
`flate2` 1 (miniz_oxide backend, pure Rust; all three already cross-compile in the tree or have
no C), `reqwest` 0.12 with rustls (already used by `waved-meeting`), `tokio` 1, `serde_json`.

**Spec:** `../TODO.md` H1–H4 and "Not planned" (no Insta360 cloud); `../docs/mockups/png/ota.png`
and `../docs/mockups/index.html#ota`; `docs/DISPLAY_HARDWARE.md` "Deploy" (space, strip);
`deploy/S60waved`, `deploy/install.sh`, `deploy/revert.sh`.

## Decisions

As planned. The decisions as built are in `docs/UPDATES.md`: U6 now counts boots (two, or
ten starts in one boot), not three starts, and U10–U13 came from review.

| # | Decision | Cost if wrong |
|---|---|---|
| U1 | Package `.wup`: magic, signed JSON header, then gzip-compressed files. Signature over the header; the header holds each file's stored and unpacked SHA-256. | A custom format needs our tool to inspect (`waved-pack inspect`). |
| U2 | A closed list of targets: the waved binary and the `deploy/` files (`S60waved`, `S03splash`, `splash.fb`, `iptables.rules`, `rsyslog.conf`). No arbitrary rootfs paths, no partitions. | Anything else (kernel, rootfs libraries) still needs adb. |
| U3 | Server index `latest.json` is unsigned; the package is the authority. The index only decides whether to download. | A hostile server can make Wave download junk (rejected) — a nuisance, not a compromise. |
| U4 | Versions are `MAJOR.MINOR.PATCH` from the binary itself (`waved-pack` reads a marker in it). Equal is up to date. Lower is refused unless `security.ota_allow_downgrade = true` on the device. | Every release must bump the workspace version. |
| U5 | Download to `/tmp/waved-update/` (RAM), stage in `/data/waved/update/staged/`, rename into place. | A reboot mid-download restarts the download. |
| U6 | Trial boot: `update/trial` lists what to restore; `S60waved` counts starts in `update/starts` and rolls back after 3 starts without a commit. waved commits after 60 s up with capture healthy. | A binary that hangs without exiting is only rolled back after the user power-cycles it three times. |
| U7 | Install waits until nothing is in use (recording, decision, call, ringing, computer listening, playback, Wi-Fi setup). A manual install ignores "computer listening". A version that rolled back is skipped by automatic checks. | A computer that never closes the mic stream blocks automatic installs. |
| U8 | Reboot after install with `/sbin/reboot` (orderly rcK). | Unverified on the device. |
| U9 | The trusted key comes from `WAVED_UPDATE_PUBKEY` at build time. A build without it shows "Updates are off" and refuses every package; `waved-pack` refuses to pack a binary that does not embed the signing key's public half. | A build made without the key can only be updated over adb. |

## Tasks

- [x] **T1 Version and key** — `version.rs`, `key.rs`. Tests: ordering, parse rejects, downgrade
  refusal and the explicit allowance, the marker carries the crate version.
- [x] **T2 Package format** — `format.rs`, `elf.rs`. Tests: round trip; tampered header, payload,
  signature and wrong key are rejected; trailing bytes, oversize header, unknown target, path
  outside staging, size lies; nothing is decompressed before its stored hash matches.
- [x] **T3 Server index** — `index.rs`. Tests: parse, relative and absolute package URLs, bad hash,
  oversize.
- [x] **T4 Trial and fall-back** — `trial.rs` plus the guard in `deploy/S60waved`. Tests: the
  Rust classification (trial, interrupted install, rolled back, normal), commit, and the shell
  guard run with `sh` on a temp dir (counts, rolls back on the fourth start, restores aux files,
  leaves a normal start alone).
- [x] **T5 Installer** — `install.rs` (`Installer` trait, `FsInstaller`, `RecordingInstaller`),
  `space.rs`. Tests on a temp root: files land with modes, `.prev` kept, trial written before the
  binary swap, init scripts syntax-checked, space plan reclaims `waved.prev` only when committed.
- [x] **T6 Gate and health** — `gate.rs` (health lives there too). Tests per blocker, manual vs automatic.
- [x] **T7 Fetcher and service** — `fetch.rs`, `service.rs`. Tests with a fake fetcher and paused
  time: up to date, download+verify+install+reboot with progress, interrupted download resumes,
  corrupt download never installs, downgrade refused, waits for a recording to end, a rolled-back
  version is skipped automatically but a manual install tries it, commit after health.
- [x] **T8 Contracts** (hotspots, additive) — `waved-state`: `OtaState`, `OtaPhase`,
  `StateBus::ota`, two commands. `waved-config`: `security.ota_allow_downgrade`. Tests in each.
- [x] **T9 Screen** — `screens_v2/ota.rs` (`UpdateScreen`), registry, router takeover while
  installing, System row "Firmware update". Goldens: `update_installing` (ota.png),
  `update_failed`, and `screen_system` regenerated (Firmware update row, system.png). The
  waiting state is covered by text assertions, not a golden.
- [x] **T10 Tool** — `src/bin/waved-pack.rs`: `keygen`, `pubkey`, `pack`, `inspect`. Test the
  library functions it calls.
- [x] **T11 Wiring** — `main.rs` spawns the service (device paths, HTTP fetcher, FsInstaller);
  `Cross.toml` passes `WAVED_UPDATE_PUBKEY`. The wiring is `waved_update::device::spawn_device`
  (host-tested); the one call in `main.rs` is unchecked here: `scripts/linux-test.sh check -p
