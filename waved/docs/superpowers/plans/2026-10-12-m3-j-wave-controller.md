# M3 J — Wave Controller ("PC Link") Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** waved answers the official Wave Controller app over vendor HID report 0x03 the way stock 1.2.2.6 does (TODO J1–J4). J5 (checking against the real app) is out of scope.

**Architecture:** One shared MAVLink v2 codec crate (`waved-mavlink`) carries the stock 24-message table; `waved-mcu` keeps its API on top of it. `waved-hid` gets a `pclink` module built as pure layers (vendor report → reliable transport → MAVLink → 16-byte PC-link packets → command handler), composed in one `PcLink` engine that takes reports and a device snapshot in and gives reports and bus commands out, with time passed in. A thin service runs it on threads: the existing `HidReader` forwards report 0x03, a writer thread owns the PC-link writes to `/dev/hidg0`.

**Tech Stack:** Rust, std threads + `std::sync::mpsc`, `tokio::sync::{watch, broadcast}` (sync use only), no new external dependencies.

**Spec:** `waved/docs/WAVE_CONTROLLER_PROTOCOL.md` (J1, written first from the decompiled 1.2.2.6 code, DWARF and ELF tables).

## Decisions

- **Shared codec crate** `waved-mavlink` (no deps) instead of a copy: both links use the same stock table; `waved-mcu::mavlink` becomes a thin wrapper with an MCU-only subset so its parser behaves as before.
- **Wire behaviour mirrors stock** where the app can see it (field layouts, 0xFF padding, ack seq `FF FF FF FF`, flags, timings, "no ack" for ids without a stock handler). Stock's uninitialised fields are sent as zeros.
- **Unsupported = stock ack size, zeros, result byte 1** at the stock result offset (meeting op keeps stock's 7; set-timezone keeps stock's 0xFF).
- **No serial numbers** in any reply (`devSN`, `usbId` use stock's fallbacks).
- **Never bound, never encrypted:** binding/cloud/OTA/factory/debug commands are unsupported; AUTH_DEV answers "not bound".
- **PIN check behind a trait** (`PinVerifier`), default denies; integration wires K2's check. Device-side prompt is an optional channel; without it a PIN-protected request fails at once.
- **Clock setting behind `PcLinkHost::set_time`**, default "unsupported".
- Mode mapping (J4): 1 Follow talker, 2 Whole room, 3 Focused, 4 Narrow, 5 Two sides, 6 Stereo.

## Tasks

- [ ] **1. `waved-mavlink` crate** — `MsgSpec`, stock table (24), `MCU_LINK`/`PC_LINK` subsets, `encode(table, header, msgid, payload)`, `Parser::new(table)`, `Message {seq, sysid, compid, msgid, payload}`. Tests: CRC-16/MCRF4XX check value, stock MCU frames, PC frame fixture, compid carried, trimming. Port `waved-mcu::mavlink` onto it; its tests stay green.
- [ ] **2. `pclink::vendor`** — 64-byte report encode/decode (types 0–6), heartbeat request detection, 0xEF response. Byte-exact tests from `change_hid_vendor_package_to_carry` and `transfor_short_heartbeat_to_carray`.
- [ ] **3. `pclink::transport`** — tx: 52-byte chunks, ids from 1, pool 1200, RESEND → RESEND_RESP (30 ms limit), SYNC after 300 ms idle; rx: in-order delivery, gap → RESEND (first at once, ≥61 ms, ≤21, 10 per 100 ms round), give up, SYNC → SYNC_RESP, RESET → RESET_RESP + reset signal, > 400 jump restarts.
- [ ] **4. `pclink::packet`** — header encode/decode, segmentation (flags 0x25/0x45/0x05, `FF` padding, ack seq −1), reassembly with a 64 KiB cap.
- [ ] **5. `pclink::status`** — CRC-8, 318-byte device status (bit positions from DWARF), 58-byte short heartbeat, change detection for pushes.
- [ ] **6. `pclink::mode`** — J4 table both ways.
- [ ] **7. `pclink::handler`** — every id from the handler table (§6 of the doc): replies, bus `Command`s, session token check, AUTH/UNAUTH, VERIFY_DEV_PASSWD state machine, MEETING_PC_STATUS record.
- [ ] **8. `pclink::link`** — `PcLink` engine: report in → delivered MAVLink → packets → handler → acks → MAVLink → transport → reports; heartbeat push policy; OB channel. End-to-end tests with fixtures generated by an independent Python model of the stock code.
- [ ] **9. Runtime** — `HidReader::spawn_with_vendor` forwards report 0x03 (`spawn` unchanged); `pclink::service` (engine thread + writer thread, snapshot from `StateBus`); `main.rs`: three additive lines in the HID block.
- [ ] **10. Docs** — `waved-hid` README section, `docs/FIRMWARE_GAP_ANALYSIS.md` row, `TODO.md` J1–J4 ticks, doc open questions.
